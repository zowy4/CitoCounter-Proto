## 1. Estrategia General

La estrategia de anonimización para CitoCounter-Proto sigue un enfoque de **minimización de datos** y **pseudonimización** donde sea posible, con el objetivo de:

- **Nunca almacenar** identificadores personales en metadatos públicos o reportes
- **Pseudonimizar** cuando sea necesario mantener trazabilidad interna
- **Agregar** datos para reportes estadísticos
- **Eliminar** datos identificables antes de cualquier salida pública

### 2.6. Reportes y Salidas Públicas

| Tipo de Salida | Datos Permitidos | Datos Prohibidos |
|----------------|-----------------|------------------|
| **Reporte CSV/JSON** | `total`, `normales`, `sospechosas`, `porcentaje_normal`, `porcentaje_anormal` | Nombres de archivo, `patient_id`, `fecha`, IDs individuales |
| **Panel comparativo** | Imagen con contornos, títulos genéricos | Nombres de paciente, IDs, fechas |
| **Respuesta API (`api_v1.py`)** | `count`, `percentage_normal`, `percentage_abnormal`, `warning` | Cualquier campo con identificador de paciente |
| **Interfaz Streamlit (`app.py`)** | Gráficos, métricas agregadas, `st.caption` con aviso | Datos de paciente en cualquier elemento visual |

## 4. Validación de Anonimización

### 4.1. Checklist Before Cualquier Salida Pública

- [ ] `patient_id` removido de metadata
- [ ] `nombre_archivo` removido de metadata  
- [ ] `fecha_registro` removido de metadata
- [ ] No hay nombres de pacientes en reportes CSV/JSON
- [ ] No hay nombres de pacientes en paneles de imágenes
- [ ] Advertencia "no diagnóstico" presente
- [ ] Tamaño de imagen ≤ 64 KiB validado
- [ ] Distribución de clases reportada como agregados (99.5%/0.5%)

### 4.2. Tests Automatizados (pending - tests/test_privacy.py)

1. `test_no_patient_id_in_output()` - No hay patient_id en ninguna salida

3. `test_advertencia_presenten_todas_las_salidas()` - Advertencia en CLI, Streamlit, API
4. `test_tamano_imagen_maxim_64k()` - Validar tamaño máximo
5. `test_distribucion_clases_agregadas()` - Solo proporciones, no individuos
